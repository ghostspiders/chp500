## 3. 数据流（Pipeline）

```
[Universe] --(A+HK+ADR 合并)--> [Filter] --(ST/上市/流动性/盈利/市值)-->
[Sector Allocate] --(行业配额)--> [Weight] --(自由流通加权+上限迭代)-->
[Rebalance] --(调样/缓冲/快速纳入)--> [Committee] --(裁量/复核，非全自动定稿)-->
[Index Series] --(价格/全收益 + Divisor)--> [Viz / Backtest]
```

每个阶段输入输出为 pandas DataFrame，字段统一（含 `entity_id`、`market`、`sector`、`float_mcap_cny`、`weight` 等），便于串联与缓存。

## 4. 配置落地（config.yaml）

将方法论 §10 的参数表固化为 `config.yaml`，例如：

```yaml
target_count: 500
base_currency: CNY
mcap_min: 400_0000_0000        # 未调整总市值门槛（CNY，委员会动态区间 300~500 亿）
iwf_min: 0.20                  # 自由流通比例下限
iwf_delist_threshold: 0.50     # 跌破则剔除
liquidity_ratio_min: 1.0       # 6 个月月均成交量 / 自由流通股数
listing_min_months: 12
require_4q_positive: true      # TTM 4 季累计净利为正
sector_scheme: GICS            # 退化选项: CITIC
sector_cap_mode: passive       # passive | soft
max_sector_weight: 0.20        # 仅 soft 模式
single_cap_mode: monitored     # monitored | hard | none
cap_single: 0.10               # 仅 hard 模式
rebalance_freq: quarterly
iwf_refresh: weekly
buffer_low: 400
buffer_high: 550
fast_entry_rank: 50
committee_discretion: true     # 委员会裁量（非全自动定稿）
include_bse: false
convergence_tol: 1e-6
data_source: akshare
```

## 5. 数据缓存策略

- **行情/财务**：按 `(symbol, market, as_of)` 缓存为 parquet，避免重复请求 AkShare（其有访问限速）。
- **汇率**：日频序列缓存，回测时直接读取历史汇率。
- **point-in-time 库**：构建一次（含已退市标的），后续增量更新；是回测可信度的基础。
- 缓存目录默认 `cn500/.cache/`，可在 `config.yaml` 覆盖。

## 6. 可视化看板（streamlit + plotly）

页面规划：
1. **成分权重表**：当前再平衡日 500 只成分、权重、行业、市场、市值。
2. **行业分布**：饼图/柱状图（按权重），对比上限 20%。
3. **历史走势**：价格指数 vs 全收益指数，叠加沪深 300 / 中证 A500 对比。
4. **个股权重 TOP20**：条形图。
5. **再平衡变更**：本次纳入/剔除清单（与上一期 diff）。

运行：`streamlit run cn500/viz/app.py`（本地）。

---

## 7. 回测流程（backtest.py）

1. 选定回测区间 `[start, end]`。
2. 按调样频率，用 **point-in-time** 数据重建每个再平衡日的历史成分。
3. 计算指数日度序列（价格指数 + 全收益）。
4. 输出绩效：年化收益、年化波动、夏普、最大回撤。
5. 与基准（沪深 300、中证 A500）对比，验证"全域覆盖 + 盈利筛选"是否带来更优风险收益。

> 关键：所有历史取数必须 point-in-time，严禁生存者偏差（见方法论 §9）。
